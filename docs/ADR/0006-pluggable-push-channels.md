# ADR-0006：推送渠道可插拔，站内为兜底，外部渠道失败不影响主流程

- 状态：已采纳
- 日期：2026-10-20

## 背景

题目说「推到哪里由你自己决定」。真实推送渠道（飞书/邮件）都需要外部配置；而评审环境未必有。要求既真实、又零配置可体验。

## 决策

- 抽象 `Notifier` 接口（`send(briefing) -> DeliveryResult`），实现三个通道：
  - `web`：简报落库，前端查看（始终可用，作为兜底）；
  - `feishu`：群机器人 Webhook（支持签名校验）；
  - `email`：SMTP（SSL/STARTTLS）。
- 通道由用户的 `channels` 偏好 + 服务端配置共同决定；未配置/发送失败写入 `deliveries(status=skipped|failed)`，**不抛异常中断主流程**。
- 每次推送结果落库，前端简报详情可看到「推送记录」。

## 理由

- 推送是"最后一公里"，失败不应该浪费一次已经成功的 Agent 运行；
- 可插拔设计让评测者能按自己的账号配置体验真实推送；
- `deliveries` 表让推送行为可审计（失败重试与幂等的取舍）。

## 代价

- 需要处理各渠道差异（飞书卡片 vs 邮件 HTML）；
- 未做重试队列（演示场景可接受，真实生产应引入 outbox + 重试）。

## 备选方案

| 方案 | 放弃原因 |
|---|---|
| 只做邮件 | 配置门槛高，且国内邮箱授权码复杂 |
| 只做站内 | 不满足"推送"语义 |
| 引入消息队列 | 3 天内过度设计 |

# ADR-0002：工具沙箱 —— 目录 jail + 命令白名单，而不是直接给模型裸奔能力

- 状态：已采纳
- 日期：2026-10-20

## 背景

题目要求实现 `list_dir / read_file / search_content / write_file / bash` 五个工具。这些工具一旦交给 LLM，模型（或恶意注入的网页内容）就可能诱导越权读写、执行危险命令。题目同时要求「密钥不得硬编码」，说明评审重视安全意识。

## 决策

1. **文件工具**：所有路径先 `resolve()` 归一化，必须位于 `WORKSPACE_DIR` 内；拒绝绝对路径、`..` 逃逸、符号链接指向外部；读/写/列目录各有大小与条数上限。
2. **bash 工具**：只允许白名单命令（`date`、`wc`、`head`、`tail`、`cat`、`ls` 等只读命令），**不经过 shell**（`subprocess` 直接执行参数数组），显式拒绝包含 `| & ; > < $( ) ` 反引号` 的输入；限定 cwd 在 workspace 内；超时强杀；输出截断。
3. 工具参数一律经过 JSON Schema 校验后才进入 handler。

## 理由

- 演示环境是单机、无容器编排；白名单 + 无 shell 组合子可以用极低成本挡住命令注入与横向移动；
- 文件 jail 让「模型决定调用顺序」这件事可以放心演示，而不担心它读到 `.env` 或系统文件；
- 安全边界写在代码里、并有单测覆盖，取舍都有依据。

## 代价

- 白名单会限制模型「自由发挥」，例如它想用 `curl` 抓网页会失败——因此我们提供了专门的 `fetch_url` 工具；
- 生产环境仍需容器/seccomp/firejail 等更强隔离（见后续）。

## 备选方案

| 方案 | 放弃原因 |
|---|---|
| 直接 `shell=True` 执行 | 注入面过大，不可接受 |
| Docker 每工具一个容器 | 演示环境过重，5 分钟跑通的目标做不到 |
| 完全禁用 bash | 题目明确要求实现 bash 工具 |

# ADR-0004：提供 mock LLM 离线模式，保证零密钥可体验

- 状态：已采纳
- 日期：2026-10-20

## 背景

评审拿到仓库时不一定愿意/能够配置 LLM API Key；但产品价值又依赖真实模型。CI 也需要稳定、不花钱、不发外部请求的测试。

## 决策

`LLM_MODE=real|mock` 双模式：

- `real`：调用 OpenAI 兼容 API（默认 DeepSeek）；
- `mock`：`MockLLM` 按「偏好 + 历史」生成**确定性的**工具调用序列（先 `list_dir` → `search_content` → `search_news` → `fetch_url` → `write_file` → `publish_briefing`），走完整真实循环与工具实现，只把模型替换掉。

单元测试一律使用 mock 或更小的假模型；前端顶部显示当前模式徽标。

## 理由

- 评审零配置即可看到完整流程与轨迹（但会明确标注 mock，不假装是真实 LLM）；
- CI 不依赖外部 API，稳定、免费；
- mock 的序列仍然经过 `loop.py` 的通用循环，因此也能验证「工具顺序由模型决定」的机制（不同偏好触发不同分支）。

## 代价

- mock 的"智能"是脚本化的，评审若要真实效果需配置 Key（README 已说明）；
- 需要维护 mock 分支，避免它悄悄偏离真实循环（用集成测试保证两者走同一执行路径）。

## 备选方案

| 方案 | 放弃原因 |
|---|---|
| 只做 real 模式 | 评审可能因无 Key 而无法体验，验收风险高 |
| 录制真实响应做回放 | 引入快照维护成本，且无法覆盖不同偏好 |
